# GHTrend · GitHub 星速榜

> 每天花 1 分钟，知道过去 24 小时 GitHub 上谁的 star 涨得最快。

GitHub 官方 Trending 看的是"当日活跃度"，不回答"**今天谁涨星最快**"。这个工具就干这一件事：每天抓一次候选池，和昨天的快照做差，排出一份**真实的 star 增量榜**，配中文摘要，推到你的企业微信或邮箱。

产品需求文档见 [PRD.md](PRD.md)。

---

## 打开方式

### 0. 桌面应用（Electron 版，推荐）

如果你拿到的是打包好的 **`GHTrend` 文件夹**（或安装包），直接双击 **`GHTrend.exe`**，
不需要装 Python、不需要命令行、不会闪黑框。

应用内部会自动拉起本地数据服务，窗口关掉时后端一并退出，不留后台进程。
数据都存在 exe 同级的 `data/`，日志在 `logs/`，配置是 `config.json`。

结构上是一层薄外壳（Electron）+ 原有 Python 引擎：

```
GHTrend.exe                    ← 窗口外壳，负责起停后端、拦截外链到系统浏览器
resources/app.asar             ← 外壳代码（main / preload / 加载页）
resources/backend/             ← PyInstaller 打包的 Python 后端（自带运行时）
config.json  data/  logs/      ← 用户数据，和 exe 同级，可随时备份/迁移
```

重新构建桌面版见文末「打包桌面版」。

下面两种方式适合改源码、调试或没有图形环境时使用。

### 1. 桌面图标（推荐，最省事）

双击桌面上的 **「GitHub 星速榜」**，几秒后会弹出一个**没有地址栏、没有标签页**的独立窗口——看起来就是一个桌面应用。

> 如果桌面上没有，双击项目里的 `打开界面.bat`，效果完全一样。

窗口里能做的事：

| 区域 | 说明 |
|---|---|
| 顶部四个指标卡 | 今日增量合计、上榜项目数、候选池规模、数据日期 |
| **抓取最新数据**（绿色按钮） | 立即抓取。抓取时顶部会出现**实时进度条**，进度文字来自抓取引擎的真实日志 |
| 语言 / 展示条数 / 最小增量 | 筛选条件，改完立即生效，不需要点按钮 |
| **榜单列表** | 每行**以一句大白话开头**（点它展开详情），下面是小字项目名，右侧是增量与总 Star，**右下角有「在 GitHub 查看」** |
| **退出**（右上） | 关闭窗口时一并关掉后台服务，不留僵尸进程 |

**实时推送已就绪**：页面和本地服务之间是一条 SSE 长连接（右上角「实时已连接」就是它）。抓取进度是实时推过来的；将来加"每天 8:30 自动更新"，服务端广播一条事件，页面就会自己刷新，前端一行都不用改。

### 2. 命令行菜单

双击项目里的 `启动.bat`，得到一个纯文本菜单，适合不想开窗口的时候：

```
  今日快照：已存在（698 个仓库） ｜ 本地 1 天快照（明天起可算日增）
──────────────────────────────────────────────────────────────────
  1  查看今日榜单            ← 最常用，直接看结果
  2  演示模式 · 不联网        ← 第一次用，先看它长什么样
  3  抓取 / 更新今日数据      ← 约 1 分钟，建立今天的数据快照
  4  生成日报并推送
  5  查看当前配置
  0  退出
```

### 3. 直接敲命令

```bash
python ghtrend.py demo          # 零配置、不联网，先看看它长什么样
python ghtrend.py fetch         # 抓取今天的快照（建立基线）
python ghtrend.py top           # 看榜单
python server.py                # 启动界面（不自动开窗口时加 --no-browser）
```

> **关于"为什么要等一天"**：日增榜的本质是"今天和昨天的 star 数相减"。第一次运行时本地没有任何历史快照，物理上算不出增量。此时工具不会报错，而是**自动降级为「新星榜」**——按 `star 数 ÷ 项目年龄` 排出爆发速度最快的项目。这是个诚实且有信息量的替代方案。
>
> 所以：**先抓一次把基线建起来**，越早抓，越早看到真正的日增榜。

**环境要求**：Python 3.9+。没有任何第三方依赖，不需要 `pip install`。

## 人话总结（给不懂技术的人看）

榜单里每个项目，**第一眼看到的不是技术名，也不是「图像工具」这种分类，而是一句完整的话**——说清这是个什么、或者它能帮你干什么：

```
┌────────────────────────────────────────────────────────────────┐
│ 1  像请了个随叫随到的私人助理，把 Python 环境        +1,180     │
│    里那些容易乱套的东西全替你归位                                │
│    astral-sh/uv  ·  Rust  ·  [AI 人话]                  48,000★ │
│    ──────────────────────────────────────────────────────      │
│                                          在 GitHub 查看 →      │
└────────────────────────────────────────────────────────────────┘
```

**为什么不用分类名**：「图像工具」「AI 智能体」这种标签，对不懂技术的人来说等于没说——你要么本来就知道它是什么，要么还是一头雾水。所以标题要求写成"人话句子"，允许用比喻，长度 25–45 字。

点标题**展开详情**，是一段 200–300 字的正经分析（格式示意，实际内容由模型按 README 生成）：

> 这是一个……，面向……。它把原来需要……才能完成的事收进一个工具里。核心用法是……（README 写了才出现）。适合……的场景，前置条件是……，采用……许可。

### 两段提示词是怎么定的

**起标题**（25–45 字，一句话）：

- 不要只写分类名词，那等于没说
- 可以用比喻，让不懂技术的人有画面感
- 必须是完整句子，不能压缩成名词短语
- 只依据 README，不编造

**写详述**（200–300 字，四段连成一段，不带小标题）：

1. 一句话定位：是什么、给谁用
2. 解决的问题：替代或简化了哪类原有痛点
3. 核心用法：最主要的 1–2 个使用方式或命令（README 有才写）
4. 适用场景与门槛：什么情况值得用，前置条件（语言、依赖、平台、License）

硬性约束：只用 README 里的信息、不补充先验知识；禁用「强大」「革命性」「一站式」「赋能」这类营销词；技术名词保留英文原文（Docker、CLI、API、SDK）；版本号与命令必须与原文一致；信息不够宁可写短，不许凑字；结尾不加「总之/综上所述」。

完整提示词在 `ghtrend.py` 的 `PLAIN_SYSTEM_PROMPT`，你可以直接改。

这套东西的工作流程是：

1. 逐条抓取项目的 README（优先走 raw 域名，不消耗 API 配额）
2. **洗掉**徽章墙、图片、HTML 标签、代码块——这些对"这项目是干什么的"毫无帮助，反而会干扰判断
3. 交给 LLM：一次调用同时产出「人话标题」和「200–300 字详述」（提示词见下）
4. 结果缓存到 `data/plain_summaries.json`

**详情面板里的「在 GitHub 查看 →」在每行右下角，默认点开就是 github.com 官方页面。**

> 这里踩过一个坑：曾把链接默认设为「自动」，跟着抓取线路走。结果抓取走镜像时，
> 点开项目会被带到第三方加速站，而不是 GitHub。**抓取走哪条线是为了能拿到数据，
> 用户点开看哪里是为了看官方页面**，这两件事不该耦合，已解耦。

### 必须配 LLM，否则只是规则标签

这一点得说清楚，不能让你误以为已经成了：

| 是否配置 LLM | 你会看到什么 | 圈外人能看懂吗 |
|---|---|---|
| **没配** | `一个用 JavaScript 写的开源项目`、`一个用 Rust 写的图像 / 照片工具`——能读通，但只说得清「是什么」，说不出「能干什么」（徽章显示「规则标题」） | ⚠️ 勉强，只是把分类换成了一句人话 |
| **配了** | `像请了个随叫随到的私人助理，把 Python 环境里容易乱套的东西全替你归位` | ✅ 有画面感，能一眼判断跟自己有没有关系 |

规则引擎再怎么调，也没法把英文 README 翻成"人话"——**这类判断只能靠大模型**。

### 怎么配：用向导，不用手改 JSON

**第一步** 双击 `启动.bat` → 选 **8**（配置 AI 人话总结）。或者命令行 `python ghtrend.py setup`。

**第二步** 选服务商：

```
  1  DeepSeek（推荐：便宜、中文好）
  2  阿里通义千问（新用户有免费额度）
  3  智谱 GLM（有免费的 glm-4-flash）
  4  本地 Ollama（完全免费、数据不出门，但要先装软件）
  5  自定义（任何 OpenAI 兼容接口）
  0  取消
```

**第三步** 按提示去注册、复制密钥、粘贴回来。

向导会自动做完剩下的事：

- 用一句最短的请求**当场验证密钥能否用**（不是只写文件就完事）
- 验证通过才写入 `config.json`；**失败会告诉你可能原因，并且不写配置**，不会把你原来的设置弄乱
- 告诉你回界面刷新即可看到效果

```
  正在测试能不能连通…
  ✔ 通了（模型回复：正常）
  ✔ 已写入：...\config.json
```

界面刷新后，右上角出现「人话总结 3/20」，标题会一条条变成大白话。

### 不想用向导？手改配置也行

```json
{
  "llm": {
    "enabled": true,
    "base_url": "https://api.deepseek.com/v1",
    "api_key": "sk-你的密钥",
    "model": "deepseek-chat",
    "max_calls_per_run": 30
  }
}
```

或用环境变量 `GHTREND_LLM_ENABLED=1` / `GHTREND_LLM_BASE_URL` / `GHTREND_LLM_API_KEY` / `GHTREND_LLM_MODEL`。

> ⚠️ `config.json` 里有密钥，**不要提交到代码库、不要发给别人**。项目已带 `.gitignore` 把它排除。

几个可选服务商（都兼容 OpenAI 格式，改 `base_url` + `model` 即可）：

| 服务 | base_url | 参考模型 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |

**成本**：Top 20 每条调一次、每天一次，缓存后仓库不更新就不重复调用。按 DeepSeek 的价格，**一天不到一分钱**。

### 界面怎么看

配置后打开界面，左上角会显示「**人话总结 3/20**」的进度，标题会**一条一条变成大白话**（走的是和抓取同一套实时推送通道）。徽章从灰色的「规则标题」变成蓝色的「AI 人话」。

命令行也能用：`python ghtrend.py daily --plain --report`，报告里每个项目会以人话标题开头。

## 连不上 GitHub 怎么办（无加速器方案）

这是最常卡住的一步。`api.github.com` 在国内经常连不通或极慢，程序会抓不到数据。

### 程序是怎么处理的：自动换线路

**不需要你手动配任何东西。** 每次抓取前，程序会按优先级现场探测，选中**第一条真正能返回 GitHub 数据的**线路：

| 优先级 | 线路 | 说明 |
|---|---|---|
| 1 | `api.github.com` 直连 | 最稳，不经过第三方 |
| 2 | gh-proxy 加速 | 公共镜像，实测支持 Search API |
| 3 | ghfast / kkgithub / llkk | 备用镜像，失效时自动跳过 |

选中的结果会缓存 24 小时，不会每次启动都重新探测。抓取中途整条线路失败，还会**重新探测并重试一次**。

**探测不是只看 HTTP 状态码**——镜像挂了常常返回 200 + 一个 HTML 错误页，光看状态码会误判成"可用"。所以还要校验响应里有没有 GitHub API 的特征字段。

想直观看结果：

```bash
python ghtrend.py netcheck        # 或双击 启动.bat 选 7
```

```
  线路                状态      结果
  ✔ GitHub 官方直连     可用      443 ms
  本次将使用：GitHub 官方直连
```

全部不通时会明确告诉你试过哪些、下一步该做什么，而不是丢一个 `ConnectionError` 给你。

### 三种方案，按推荐顺序

**方案 A：用自己的加速器（最稳）**

打开加速器/代理后直接运行即可，程序会自动识别到直连通了。如果加速器只给了一个「反代地址」，填进配置：

```json
{ "github": { "api_base": "https://gh.你的域名.com" } }
```

填了 `api_base` 就**不再自动探测**——程序会尊重你的选择，也不会偷偷换成第三方镜像。

**方案 B：用公共镜像（零配置）**

什么都不用做，程序默认就会用。适合「不想折腾、先跑起来看看」。

**方案 C：自建 Cloudflare Worker 反代（免费、稳定、可控）**

不依赖别人的镜像站，也不怕它哪天挂了。免费额度足够这个工具用。

1. 打开 https://dash.cloudflare.com → Workers & Pages → 创建 Worker
2. 贴上这段代码，部署：

```js
export default {
  async fetch(request) {
    const url = new URL(request.url);
    const target = "https://api.github.com" + url.pathname + url.search;
    const res = await fetch(target, {
      method: request.method,
      headers: {
        "Accept": request.headers.get("Accept") || "application/vnd.github+json",
        "User-Agent": "ghtrend-proxy",
      },
    });
    const body = await res.text();
    return new Response(body, {
      status: res.status,
      headers: {
        "Content-Type": "application/json; charset=utf-8",
        "Access-Control-Allow-Origin": "*",
      },
    });
  },
};
```

3. 得到一个 `https://xxx.workers.dev` 地址，填进 `config.json`：

```json
{ "github": { "api_base": "https://xxx.workers.dev" } }
```

> 注意：`*.workers.dev` 本身在部分网络下也访问不了，此时需要给它绑一个自己的域名。

### 第二个坑：数据有了，项目点不开

榜单能看了，但点项目名还是打不开 github.com —— 这是同一个问题的另一半，很容易被忽略。

界面工具栏里有个「打开项目」下拉框，**默认是 github.com 官方**。直连打不开时切到 **gh-proxy 加速**，之后点项目名就会走镜像打开。选择记在浏览器里，下次不用重选。

想改选项或加自己的镜像，编辑 `config.json` 的 `web.link_modes`：

```json
{
  "web": {
    "link_modes": [
      { "id": "direct",  "label": "github.com 官方", "template": "{url}" },
      { "id": "ghproxy", "label": "gh-proxy 加速（直连打不开时选）", "template": "https://gh-proxy.com/{url}" }
    ],
    "default_link_mode": "direct"
  }
}
```

- `{url}` = 完整地址 `https://github.com/owner/repo`
- `{path}` = 只有路径 `owner/repo`

### 全都不通时还能干什么

程序**不会把你锁死**。已有历史快照照常能看：

- 界面打开就有榜单（本地数据，不需要网络）
- 命令行走的是「回退上次快照」逻辑，会明确标注「数据非最新」
- `--offline` 参数可以强制只用本地数据

### 得说清楚的三个风险

1. **公共镜像是第三方**。你的请求（包括 Token，如果配了）会经过它。**所以：走了第三方镜像时，不要配 GitHub Token**，或者用自己的反代。
2. **公共镜像随时会挂**。今天能通不代表下周能通。所以程序是"现场探测"而不是"写死一个"。真长期使用，建议方案 A 或 C。
3. **镜像可能被中间人篡改**。这是所有第三方代理的固有问题。榜单数据只是趋势参考，不涉及账号操作，风险可控；但别把 Token 交给来路不明的镜像。

## 命令速查

| 命令 | 作用 |
|---|---|
| `python ghtrend.py demo` | 用内置示例数据跑通全流程，**不联网、零配置** |
| `python ghtrend.py fetch` | 抓取候选池，保存今日快照 |
| `python ghtrend.py top` | 展示榜单（今日无快照会自动抓取） |
| `python ghtrend.py daily` | **一键日报**：抓取 + 榜单 + 摘要 + 报告 + 推送（定时任务用这个） |
| `python ghtrend.py show <owner/repo>` | 查看某仓库在本地快照里的 star 历史曲线 |
| `python ghtrend.py netcheck` | **探测哪条 GitHub 线路能通**（连不上时先跑这个） |
| `python ghtrend.py setup` | **配置 LLM 的向导**（粘贴密钥即可，自动测试连通性） |
| `python ghtrend.py pack` | **打包成可发给别人的压缩包**（自动剔除密钥与本地数据） |
| `python ghtrend.py init` | 生成配置模板 `config.example.json` |
| `python ghtrend.py config` | 查看当前生效配置（密钥只显示"已配置/未配置"） |

### 常用参数

```bash
# 只看 Python 项目的 Top 10
python ghtrend.py top --language python --top 10

# 只要今天涨了 100 星以上的
python ghtrend.py top --min-delta 100

# 输出 JSON，方便自己接 Grafana / 表格 / 二次加工
python ghtrend.py top --format json > today.json

# 输出 Markdown（可直接贴到飞书/Notion/公众号）
python ghtrend.py top --format markdown

# 强制重新抓取今天的快照（默认同一天只抓一次）
python ghtrend.py fetch --refresh

# 关闭 AI 摘要，只用离线规则引擎
python ghtrend.py top --no-ai
```

| 参数 | 说明 |
|---|---|
| `--top N` | 展示条数，默认 20 |
| `--language LANG` | 按语言过滤，如 `python` / `rust` / `go` / `typescript` |
| `--min-delta N` | 最小增量门槛 |
| `--format table\|markdown\|json` | 输出格式，默认 `table` |
| `--report` | 额外生成 Markdown 报告文件 |
| `--notify` | 推送到企业微信 / 邮箱 |
| `--plain` | 额外生成「人话总结」标题（需配置 LLM） |
| `--refresh` | 忽略今日已有快照，强制重新抓取 |
| `--offline` | 禁止联网（无今日快照则报错） |
| `--transport auto\|urllib\|curl` | 网络传输层，默认 `auto` |
| `--data-dir DIR` | 数据目录，默认 `./data` |

## 配置（三步走，每步都可以跳过）

```bash
python ghtrend.py init      # 生成 config.example.json
cp config.example.json config.json   # 然后编辑 config.json
```

环境变量优先级高于 `config.json`，适合放进定时任务或 CI。

### 1. GitHub Token（可选但建议）

不配也能跑，但搜索接口配额是 **10 次/分钟**；配置后提升到 **30 次/分钟**，抓取更快也更稳。

- 打开 https://github.com/settings/tokens → `Generate new token (classic)`

## 口径说明（重要）

**日增 = 今日快照 star 数 − 基准快照 star 数**

由于两次快照的取数存在时间差，这个数字与"真实 24 小时增量"会有少量偏差。这是任何基于快照差值的方案都无法避免的。工具选择的是**把口径写在报告里**，用透明度换信任，而不是假装自己精确到个位。

- 基准快照默认取"最近一个更早的日期"。若基准距今超过 1 天，界面会切换为**日均增量**并明确标注，避免拿 3 天的累计增长去和 1 天的增长做不公平比较。
- Star 数下降（取消 star、清理刷量）会**如实显示负数**，不做归零美化。
- 榜单排序基于候选池：核心池（`star≥500` 且近 30 天有提交，取前 500）+ 新星池（`star≥100` 且近 60 天创建，取前 200）。一个真正在爆发增长的项目必然落在两者之一的范围内。

> **为什么有个 `launch.bat`**：cmd.exe 按 GBK 解析 `.bat` 文件，文件名里的中文如果出现在**脚本内容**中会乱码并导致命令错位。所以真正的逻辑放在 ASCII 文件名的 `launch.bat` 里，中文名的 `打开界面.bat` 只有一个 `call`。**所有 .bat 的内容都必须是纯 ASCII**，这是硬约束。

### 界面服务的几个接口

| 接口 | 作用 |
|---|---|
| `GET /api/board?top=&language=&min_delta=` | 榜单数据（JSON，界面和二次开发共用） |
| `GET /api/status` | 数据状态、连接数、当前任务 |
| `GET /api/events` | **SSE 事件流**：`hello` / `progress` / `job` / `board-updated` |
| `POST /api/refresh` | 触发后台抓取 |
| `POST /api/quit` | 关闭服务 |

服务只监听 `127.0.0.1`，静态文件走白名单，空闲 30 分钟自动退出。

## 后续怎么加"实时推送"

实时推送的地基已经打好了，不需要重构：

**场景一：定时自动更新**
在 `server.py` 里加一个定时线程，到点调 `start_refresh(state)` 即可。抓取完成后它已经会 `broadcast("board-updated")`，打开着的页面会**自动刷新**，前端零改动。

**场景二：推送到手机 / 企业微信**
抓取完成后调用现有的 `do_notify(ctx, cfg, ...)`（`ghtrend.py` 里已有企业微信和邮件通道），接在 `broadcast` 旁边即可。

**场景三：想换成 WebSocket**
只需要替换 `_handle_events`，其余业务代码不动——计算逻辑与传输方式本来就是解耦的。


- 快照是**纯文件、无数据库**，整个 `data/` 目录可以直接拷走迁移。
- 超过 `retention_days`（默认 90 天）的快照与报告会自动清理。

## 发给别人用

**可以。** 代码和脚本全部用相对路径（`%~dp0` / `__file__`），复制到任何目录都能跑。

### 一条命令打包

```bash
python ghtrend.py pack
```

生成 `GHTrend-可发给他人的版本.zip`（约 86 KB），并且**自动做两件事**：

1. 剔除 `config.json`（**你的 API 密钥在里面，绝不能发出去**）
2. 剔除 `data/`、`logs/`、`__pycache__`（你的本地数据和日志）

打包完会自检一遍：扫压缩包里所有文本文件，确认没有 `sk-` 开头的密钥、没有 `config.json`。不通过会直接报错。

### 对方怎么用

1. 解压，得到 `GHTrend` 文件夹
2. **双击 `打开界面.bat`**
3. 窗口打开后点「抓取最新数据」，等 1 分钟

包里有 `第一次使用请看这里.txt`，是专门写给不懂技术的人看的，不用你再解释。

### 两个前提

| 前提 | 说明 |
|---|---|
| **对方要装 Python 3.9+** | 这是唯一的硬门槛。没有的话双击会弹出英文提示，告诉他去 python.org 下载并勾选 Add to PATH |
| **仅限 Windows** | `.bat` 和 Edge 应用窗口都是 Windows 的。macOS / Linux 要手动跑 `python server.py`（功能一样，只是没有双击入口） |

### 想做到「不用装 Python 也能用」

需要打包成单个 `.exe`（用 PyInstaller 之类）。这样对方双击就能开，体积会变成 40–60 MB。

如果你要发给完全不懂电脑的人，这个更合适——需要的话跟我说，我来打。

> ⚠️ 提醒：如果你把 `config.json` 直接拷给别人（而不是用 `pack`），等于把 API 密钥送出去了。他花的钱记在你账上。

## 常见问题

**Q：连不上 GitHub / 抓取一直失败？**
先跑 `python ghtrend.py netcheck`（或菜单里选 7）看哪条线路能通。程序默认会自动换镜像，详细方案见上面「连不上 GitHub 怎么办」。已有历史快照不受影响，界面照常能看。

**Q：双击桌面图标，什么都没发生？**
先看 `logs\server.log`。服务的启动信息、异常堆栈都在里面。启动失败时程序会主动弹一个系统消息框告诉你原因（因为无控制台模式下没有别的地方能显示错误）。

**Q：提示端口 8765 被占用？**
说明服务已经在跑了，直接打开 `http://127.0.0.1:8765/` 即可；也可以 `python server.py --port 8770` 换个端口。启动器本身会先探测端口，已在运行就只开窗口、不重复启动。

**Q：界面和命令行用的是同一份数据吗？**
是。两者都走 `ghtrend.py` 的计算逻辑，读写同一个 `data/` 目录。界面抓的数据，命令行 `top` 立刻能看到，反之亦然。

**Q：第一次运行显示"新星榜"而不是"日增榜"，是出错了吗？**
不是。这是设计好的降级行为。本地没有历史快照时物理上算不出增量。先跑一次 `fetch` 建立基线，第二天就有日增榜了。

**Q：提示"GitHub 配额已用尽"？**
未认证时搜索接口只有 10 次/分钟。配置 `GITHUB_TOKEN` 可提升到 30 次/分钟。也可以调小 `config.json` 里的 `core_pages` / `new_pages` 减少请求数。

**Q：报 TLS 握手失败 / SSL 错误？**
企业网络的 SSL 解密代理经常导致 Python 的 TLS 握手失败而 curl 正常。工具**会自动回退到 curl 传输层**（日志里会看到提示）。也可以手动指定 `--transport curl`。

**Q：抓取失败会不会什么都看不到？**
不会。工具会**回退到最近一次的本地快照**并明确标注"以下为 X 月 X 日的榜单（数据非最新）"，而不是给你一个空榜单。

**Q：过滤后一条都没有？**
会输出 0 条，并告诉你候选池规模以及可能是哪个筛选条件过窄。不会报错，也不会给你空白。

**Q：榜单里的中文摘要有点生硬？**
那是规则引擎的输出（未配置 LLM 时的兜底）。它诚实地标注"官方描述：..."而不是假装翻译过。配置 LLM 后会得到真正的语义摘要。

## 已知限制

- **候选池有上限**：GitHub Search API 单查询最多返回 1000 条结果，因此无法做到全站覆盖。若发现漏检，可调大 `core_pages` / `new_pages`。
- **不做刷星识别**：v1 不区分"真实增长"与"刷量增长"，只忠实呈现数字。这是 PRD 中记录的已知风险（NG6），若将来面向公开用户必须解决。
- **需要积累**：日增榜在物理上需要至少两个不同日期的快照，无法通过加快开发来缩短。

## 打包桌面版

### 一键（Windows）

```bat
build_app.bat
```

依次做三件事：PyInstaller 打包后端 → 检查 Electron 依赖 → electron-builder 出包。
产物在 `dist/`。

### 手动三步

```bash
# 1) 后端 -> 独立 exe（自带 Python 运行时，目标机器不用装 Python）
python -m PyInstaller --noconfirm --clean --name ghtrend-server --onedir --noconsole \
  --icon electron/build/icon.ico \
  --add-data "<项目绝对路径>/web;web" \
  --distpath backend-dist --workpath build/pyinstaller --specpath build server.py

# 2) 图标（纯标准库绘制，无 Pillow 依赖）
python tools/make_icon.py

# 3) 组装外壳
cd electron && npm install && npm run dist
```

> `--add-data` 和 `--icon` **必须用绝对路径**。因为 `--specpath build` 会把相对路径
> 解析到 `build/` 下，写成相对路径会得到 `build/web does not exist`。

### 三个真实的坑（都在 Windows 上踩过）

1. **`config.json` / `data` 会凭空消失**
   PyInstaller 打包后 `__file__` 指向临时解压目录，写进去的配置和快照一退出就没了。
   代码里已用 `GHTREND_HOME` 环境变量把「数据目录」和「程序目录」拆开，
   外壳启动时把它指向 exe 同级目录。**改打包逻辑时不要动这一条。**

2. **静态资源 404**
   前端要和后端分开定位：数据看 `GHTREND_HOME`，静态文件看 `sys._MEIPASS`。
   混用会导致打包后页面空白。

3. **打包卡在 winCodeSign 解压**
   electron-builder 解压签名工具包时，里面含 macOS 的符号链接，
   普通用户权限（无 `SeCreateSymbolicLinkPrivilege`）无法创建，报
   `Cannot create symbolic link : darwin/10.12/lib/libcrypto.dylib`。
   临时办法：跳过签名编辑步骤，或手动解压剔除 `darwin/` 后放入缓存。
   只出绿色版（`--dir`）不受影响。
